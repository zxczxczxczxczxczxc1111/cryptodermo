# 0003. Открытый версионированный заголовок + зашифрованное тело

## Контекст

Формат файла должен быть читаем независимым Python-скриптом и оставаться совместимым
при будущей смене алгоритма шифрования или KDF.

## Решение

Контейнер — открытый (незашифрованный) JSON-заголовок с полями `v`, `kdf` (алгоритм и
параметры), `cipher`, `iv`, плюс зашифрованное тело `ct`. Поле `v` обязано расти при
несовместимых изменениях формата; читающий код обязан отказывать понятной ошибкой на
неизвестной версии, а не пытаться угадать структуру.

## Почему

Альтернатива — держать параметры KDF (алгоритм, число итераций, соль) внутри
зашифрованного тела ради дополнительной защиты метаданных. Отклонена: тогда для смены
алгоритма шифрования в будущем (например, PBKDF2 → Argon2id, см. ADR-0004) не было бы
способа понять, чем расшифровывать файл, до того как его расшифруешь — замкнутый круг.
Открытый заголовок раскрывает алгоритм и параметры KDF (не секрет сам по себе — соль не
даёт преимущества атакующему без пароля), но взамен даёт коду путь для чтения старых баз
после смены схемы.

## Последствия

Заголовок — единственное место, которое обязано пройти через все версии формата без
исключений; ошибка в дисциплине проверки `v` в любом будущем тикете открывает риск
молчаливо неверной интерпретации байт. Утечка одного заголовка (например, если файл
скопирован третьим лицом) раскрывает алгоритм и число итераций KDF — не пароль и не
данные, но и не ничего.
