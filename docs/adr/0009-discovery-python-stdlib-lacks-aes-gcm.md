# 0009 (D01). Discovery: в stdlib Python нет AES-GCM

## Контекст (что предполагал план)

Требование Д3 брифа гласило «Python 3, только стандартная библиотека» для аварийного
дешифратора (R24, R57, см. ADR-0006) — план предполагал, что этого достаточно для
полноценного расшифрования файла, реализующего ту же схему AES-256-GCM, что и основное
приложение (ADR-0004).

## Решение (что доказал код)

Таск 05 обнаружил, что в стандартной библиотеке Python нет AES-GCM ни в каком виде
(`hashlib`, `ssl`, `hmac` — ни один не даёт примитивов, нужных для аутентифицированного
шифрования AES-GCM). «Только stdlib» оказалось достаточно лишь для чтения открытого
JSON-заголовка, не для расшифровки тела. Пользователь решил в чате 16.08.2026: рядом с
`emergency-decrypt.py` кладётся второй текстовый файл, `aes_gcm.py` — чистая
Python-реализация AES-GCM по стандарту (FIPS-197 + NIST SP 800-38D), корректность
которой проверена официальными тестовыми векторами NIST, а не только сверкой с этим же
проектом.

## Почему

Рассмотренная альтернатива — разрешить `emergency-decrypt.py` зависеть от pip-пакета
(`cryptography` или `pycryptodome`) для AES-GCM. Отклонена по той же причине, что и
изоляция скрипта от зависимостей вообще (ADR-0006): `pip install` без интернета через
десять лет может быть недоступен, а «работает без интернета и без установки» — часть
приоритета 2, не мелочь. Написание собственного примитива AES-GCM формально похоже на
нарушение «не писать свою криптографию» (R20/R32), но реализация стандартного,
специфицированного алгоритма по опубликованным NIST-векторам — перенос существующего
стандарта на язык без встроенной поддержки, а не изобретение схемы; это прямо
зафиксировано как не-нарушение R20/R32 в момент решения.

## Последствия

Проект получает файл с ручной криптографической реализацией, которую нужно поддерживать
наравне с остальным кодом — область, где цена ошибки в тесте или ревью выше обычного
кода: баг может означать неверную расшифровку без явной ошибки. Автотест совместимости
R26 теперь неявно проверяет и `aes_gcm.py`, не только формат контейнера. Скорость
реализации не оптимизировалась осознанно (личный архив, не поток данных) — не повод для
пересмотра без явной необходимости.
